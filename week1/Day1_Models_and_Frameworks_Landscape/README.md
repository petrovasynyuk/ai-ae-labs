# Моє виконання ДЗ 1 — агент-планувальник вихідних у Рівному

Дата запуску: **04.10.2026**.
Мова: Go 1.27.1.
Базова модель: `gemini-3.8-flash` через Gemini API.

## Як запустити

1. Створити `apps/.env` з `apps/.env-example`.
2. Вказати в ньому `GOOGLE_API_KEY`.
3. З кореня репозиторію запустити:

   ```bash
   go run ./week1/Day1_Models_and_Frameworks_Landscape/labs console
   ```

Агент працює лише з плануванням вихідних у Рівному. Для актуальних подій, погоди, графіків і цін він має використовувати пошук. На запити поза доменом агент повинен відмовитися відповідати.

## Перевірка поведінки агента

### 1. План на суботу

**Запит:** `Склади план на суботу у Рівному з бюджетом до 1500 грн.`

**Результат:** агент склав маршрут із блоками «ранок», «день», «вечір» і приблизним бюджетом `1350–1480 грн`. Він запропонував сніданок у центрі, прогулянку, краєзнавчий музей, зоопарк, вечірню прогулянку та вечерю.

**Вимір:** TTFB — `11.16 с`, повна відповідь — `16.15 с`.

### 2. Уточнення про дощ

**Запит:** `А якщо буде дощ?`

**Результат:** агент змінив маршрут на приміщення: музей, галерею або підземелля, кінотеатр і вечерю. Бюджет склав `1230–1480 грн`.

**Вимір:** TTFB — `7.26 с`, повна відповідь — `12.59 с`.

### 3. Запит поза доменом

**Запит:** `Напиши програму на Go, яка сортує масив.`

**Результат:** агент ввічливо відмовився. Він пояснив, що його домен — планування вихідних у Рівному.

**Вимір:** TTFB — `2.17 с`, повна відповідь — `2.58 с`.

## Context-stress сценарій

Я передав агенту короткий штучний довідник із шістьма подіями Рівного. У довіднику була вистава в міському театрі о 18:30, але не було номера телефону організатора.

| Запит | Результат | Висновок |
|---|---|---|
| `Що можна запланувати на суботу о 18:30?` | Агент назвав виставу в міському театрі. Він не додав відсутньої ціни квитка. | Контекст у prompt допомагає, коли факт уже є в тексті. |
| `Який номер телефону організатора вистави в театрі?` | Агент відповів, що номера в довіднику немає. | Агент не повинен вигадувати дані. Для внутрішніх фактів, яких немає у prompt, потрібне джерело даних або RAG. |

Виміри: `7.77 с` для факту з довідника та `2.99 с` для чесної відповіді про відсутні дані.

## Перевірка пошуку

**Запит:** `Які події відбуваються в Рівному саме сьогодні, 4 жовтня 2026 року? Перед відповіддю обов’язково використай пошук і наведи джерела.`

Агент повернув перелік подій і посилання на OGO.ua, List.in.ua та Status Рівне. Console launcher не показав окремий технічний рядок `google_search`, тому цей запуск показує результат відповіді з посиланнями, але не є окремим трасуванням виклику інструмента.

**Вимір:** TTFB — `8.33 с`, повна відповідь — `12.32 с`.

## Міні-бенчмарк

Для порівняння я використовую однаковий prompt і змінюю тільки змінну `MODEL`.

| Модель | Латентність, мс | Якість відповіді | Приблизна вартість, USD | Станом на | Ліцензія |
|---|---:|---|---:|---|---|
| `gemini-3.8-flash` | 9 964 | Повна відповідь із конкретними локаціями та бюджетом `800–940 грн`, але вона довша за запитаний короткий формат. | ≈ $0.003 | 04.10.2026 | proprietary API |
| `gemini-3.7-flash` | 7 055 | Структурована відповідь із бюджетом `680–920 грн`; вона коротша й також виконує формат. | ≈ $0.002 | 04.10.2026 | proprietary API |

Обидва запуски використовували однаковий prompt:

```text
Склади короткий план суботи у Рівному з бюджетом до 1000 грн. Відповідь: ранок, день, вечір, бюджет.
```

Це один прогін на модель, тому результат показує вимір, а не остаточний рейтинг. `gemini-3.7-flash` була швидшою в цьому запуску на 2 909 мс. Якість оцінювалася вручну за відповідністю формату, повнотою плану та дотриманням бюджету.

Станом на 04.10.2026 стандартний тариф обох моделей становив `$0.75 / 1 млн` вхідних токенів і `$3.75 / 1 млн` вихідних токенів. Оцінка вартості приблизна: starter не виводить точні токени, тому я оцінив короткий запит та системну інструкцію приблизно у 500 вхідних токенів, а відповіді — приблизно у 600 і 500 вихідних токенів відповідно. Це не рахунок провайдера й не включає можливу окрему оплату за Google Search grounding. Джерело тарифів: [Gemini Developer API pricing](https://ai.google.dev/gemini-api/docs/pricing).

## Карта термінів

| Термін | Де це в моїй лабі | Моє пояснення |
|---|---|---|
| LLM | `gemini-3.8-flash` / `gemini-3.7-flash` | Це мовна модель, яка формує текстову відповідь на мій запит. У цій лабі я змінив модель через змінну `MODEL`, але не змінював логіку агента. |
| Prompt / instruction | Поле `Instruction` у `llmagent.Config` | Це правила поведінки агента. Я обмежив його плануванням вихідних у Рівному, задав формат відповіді та правило відмови для запитів не за темою. |
| Context window | Інструкція, історія діалогу і текст довідника в одному запиті | Це робоча пам'ять моделі в межах запиту. У тесті з довідником модель побачила подію о 18:30, але не могла назвати номер телефону, якого там не було. |
| Tool | `geminitool.GoogleSearch{}` | Це зовнішня можливість агента отримувати актуальні відомості, а не лише відповідати зі своїх загальних знань. |
| Agent | `llmagent.New(...)` разом із launcher та інструментом | Це LLM, яка працює за заданою інструкцією, за потреби використовує інструмент і відповідає користувачу через launcher. |
| RAG | У цій лабі відсутній | RAG потрібний, коли треба знайти релевантні документи з власної бази та додати їх у контекст. Для номера телефону з мого тесту це було б надійніше, ніж вигадувати дані. |
| MCP | У цій лабі відсутній | MCP — це стандарт підключення зовнішніх інструментів до агента. Тут пошук підключений безпосередньо як Go-інструмент, а не через MCP. |

## Захист ключів

Ключ Gemini зберігається в `apps/.env`, який ігнорується Git. Для комітів увімкнено `.githooks/pre-commit` через `git config core.hooksPath .githooks`. Хук запускає `gitleaks protect --staged --redact --verbose`.

Перевірку хука виконано 04.10.2026: тестовий файл із синтетичним ключем було додано до staging, після чого Gitleaks знайшов секрет і заблокував перевірку. Тестовий файл не був закомічений і був видалений зі staging та з робочої теки.

## Висновок

У цьому вимірі я обрав би `gemini-3.7-flash` для агента-планувальника. Вона відповіла швидше: 7.06 с проти 9.96 с у `gemini-3.8-flash`. Її відповідь була коротшою, але все одно мала потрібні частини: ранок, день, вечір і бюджет. Для простого планування вихідних така швидкість і достатня деталізація важливіші за довшу відповідь. Якщо з'явиться складніший сценарій із великою кількістю джерел або складними умовами, я повторно перевірю `gemini-3.8-flash`.
